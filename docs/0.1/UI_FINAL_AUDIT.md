# Torca 0.1 UI final audit

Date: 2026-08-07
Scope: UI-00 through UI-15 source state on `main`.

## Result

The 0.1 UI productization source track is complete. Release/platform validation remains open and is intentionally not represented as complete.

## Architecture boundary

PASS:

- one shared Flutter client lives under `apps/client/flutter`;
- Flutter owns presentation, responsive layout, local UI state, navigation, preferences and platform UI integration;
- Rust/runtime owns Tor, pairing, peer sessions, PeerHealth, durable messaging/retry, persistence, cryptography, attachment transfer and diagnostics data;
- no separate desktop/mobile business implementation was introduced;
- PeerHealth is computed by runtime and exposed through the bridge instead of being inferred in Flutter.

Tracked debt for 0.2 consideration: some bridge commands still accept entity IDs and timestamps generated by Flutter. This is not a 0.1 release blocker, but it weakens the presentation-only command boundary.

## Bridge and generated contract

PASS:

- active contract is v10;
- `crates/platform/torca-bridge/schema/torca_contract.dart` and `apps/client/flutter/lib/generated/torca_contract.dart` are byte-identical at blob `0ba94a0a38c5569eef8749310d9cf00a193a4451`;
- no `Bridge v9`, `torcaContractVersion = 9`, `ffi_engine_gateway_v4` or `ffi_engine_gateway_final` references were found in the active repository search;
- one canonical `ffi_engine_gateway.dart` remains.

## Product/UI state

PASS in source:

- System/Light/Dark theme persistence;
- focused Settings and shared application menu;
- reusable Tor/peer connection presentation;
- runtime-owned PeerHealth with bridge v10 DTO;
- connection details and conversation header;
- message bubbles, reply quotes, timestamps and lifecycle indicators;
- shared touch/desktop message and conversation/contact actions;
- attachment progress/actions and human-readable size presentation;
- pairing progress presentation without a second Flutter state machine;
- human-readable diagnostics overview plus raw diagnostics/self-test/export;
- Windows tray status, New pairing and notification preference behavior;
- Android user-message notification preference persisted through native host storage and read by the foreground service independently from Flutter Activity lifetime;
- desktop shortcuts (`Ctrl+N`, `Ctrl+,`, `Ctrl+Shift+D`, `Esc`), shared focus traversal and padded Material interaction targets.

## Privacy checks

PASS in source:

- no message-preview setting was introduced;
- Windows and Android notification bodies remain content-free;
- Android service notification projection remains metadata-only;
- diagnostic UI continues to consume the existing redacted diagnostics path.

## Validation still open

The following are not source-completeness claims and require owner/platform execution:

- clean Windows build and `flutter analyze` / `flutter test`;
- clean Android build and Gradle/Kotlin validation of the notification preference bridge;
- generated/accepted `pubspec.lock`;
- packaged Tor startup and onion readiness;
- two-client pairing, messaging, PeerHealth and reconnect behavior;
- exactly-once/retry/receipt restart scenarios;
- attachment interruption/resume/open/save;
- Windows tray, shortcuts, deep links and notifications;
- Android foreground lifecycle, deep links, notification preference and notification click routing;
- text scaling, keyboard traversal and accessibility inspection;
- signing/release matrix.

## Release interpretation

`UI source complete` does not mean `Torca 0.1 release validated`. The canonical release gates remain in `0.1_PROGRESS.md`, `docs/0.1/RELEASE_HANDOFF.md` and `docs/0.1/TEST_MATRIX.md`.
