## 2. Implemented production adapter source

Committed source includes:

1. `RustCryptoProvider` — Ed25519, XChaCha20-Poly1305 and operating-system CSPRNG.
2. `SqlCipherBackend`, identity repository and durable outbox/dedup stores.
3. `ManagedIdentityKeys` and the `ProtectedSecretStore` key-handle boundary.
4. Windows current-user DPAPI protected secret store.
5. Android Keystore AES-256-GCM protected secret store.
6. Versioned Flutter, Windows and Android `torca.engine.v1` channel handlers.

Adapter source does not close a release gate until production composition selects it and target tests pass.

### Attempt 6

The full Rust side is now green. Successful stages before Flutter dependency resolution:

- release metadata check;
- architecture boundary check;
- Rust formatting;
- generated contract verification;
- `cargo check --workspace --all-targets --all-features`;

Flutter then failed before package resolution because the local SDK reported Dart `3.11.5`, while Torca requires Dart `>=3.12.0` and Flutter `>=3.44.0`. The project CI baseline remains Flutter `3.44.7` on stable. This is tracked as `ENV-001`, not as a source defect.

Repository hardening added after this attempt:

- `scripts/check-flutter-toolchain.ps1` parses `flutter --version --machine` and rejects an incompatible SDK before `flutter pub get`;
- `validate.ps1` runs the preflight before Flutter dependency resolution;
- `docs/0.1/TOOLCHAIN.md` now distinguishes the CI pin from the minimum accepted local versions.
