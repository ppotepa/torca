## 2. GATE-001 — cryptography and protected keys

**Status: OPEN — production algorithms and handle composition implemented; platform stores pending.**

Implemented:

- Ed25519 signing and strict verification through `RustCryptoProvider`;
- XChaCha20-Poly1305 authenticated encryption;
- operating-system CSPRNG;
- Ed25519 and XChaCha known-answer tests plus tamper test;
- separate signing/sealing key types with redacted diagnostics;
- `ProtectedSecretStore` boundary;
- `ManagedIdentityKeys` implementing the domain `IdentityKeyProvider` while returning only `KeyId` plus public bytes;
- short-lived secret loading and best-effort temporary-memory clearing;
- test-only in-memory secret store.

Remaining:

1. Windows DPAPI/CNG protected-store implementation.
2. Android Keystore-backed protected-store implementation.
3. Host composition and owner execution of all cryptographic tests.

## 6. Dependency lock state

Production RustCrypto and SQLCipher dependencies are present in manifests. The connector environment cannot execute Cargo, so the checked-in `Cargo.lock` is stale.

Run first:

```powershell
./scripts/refresh-lock.ps1
./scripts/format.ps1
./scripts/validate.ps1 -SkipFlutter
```

Review and commit `Cargo.lock`. Validation temporarily runs without `--locked`; locked release validation must be restored after the generated graph succeeds.
