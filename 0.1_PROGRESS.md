### Attempt 8

After applying Dart formatting locally, validation stopped earlier at `Generated contract` because `apps/client/flutter/lib/generated/torca_contract.dart` had been formatted while its canonical source `crates/platform/torca-bridge/schema/torca_contract.dart` had not. The generator intentionally compares those files byte-for-byte.

This revealed `BUG-018`: the formatter operated on Flutter `lib/` and `test/`, but did not include the canonical bridge schema, so the formatter and generator could create mutually incompatible valid states.

Committed fix:

- canonical bridge schema is now in Dart 3.12 formatting;
- committed generated Dart contract is byte-identical to the canonical schema;
- `scripts/format.ps1` formats the canonical schema together with Flutter `lib/` and `test/`;
- `scripts/validate.ps1` checks the canonical schema in the same Dart-formatting gate.

### Attempt 9

Successful stages now include:

- generated contract verification and Dart formatting in the same run, **verifying BUG-018 as fixed**;
- complete Rust validation remains green;
- Flutter `3.44.9` / Dart `3.12.2` preflight;
- Flutter dependency resolution;
- Dart formatting of 13 files with **0 changes**.

Validation reached `flutter analyze` for the first time and reported five issues across three files:

1. `method_channel_engine_gateway.dart`: `MethodChannel.setMethodCallHandler` returns `void`, but disposal attempted to `await` it (`use_of_void_result`).
2. `diagnostics_screen.dart`: `ListView` was invoked as a const constructor even though it is not const (`const_with_non_const`).
3. `home_screen.dart`: three `MaterialPageRoute` constructions lacked explicit type arguments under strict inference.

These are tracked together as `BUG-019`. The committed fix removes the invalid `await`, uses a non-const `ListView` with const children, and makes all three navigation routes explicitly `MaterialPageRoute<void>` / `push<void>`. No analyzer rule was disabled.

`BUG-019` is fixed in source and awaits owner rerun verification.
