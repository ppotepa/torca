## 2. Working protocol

1. Read this file before changing the repository.
2. Work on the current batch unless explicitly redirected here.
3. Keep `main` internally consistent after every commit.
4. Update this document in the same work session as implementation.
5. Record implemented paths, decisions, limitations and one exact next action.
6. The project owner runs the full local test suite and reports results separately.
7. Pending owner tests do not block subsequent implementation unless a failure is reported.
8. Never claim tests passed without recorded evidence.
9. Every confirmed defect must be listed under **Known defects** until fixed.

### Status vocabulary

- **IMPLEMENTED** — code and documentation are present and statically reviewed;
- **VALIDATED** — owner-run local tests passed and evidence is recorded;
- **IN PROGRESS** — active implementation work;
- **BLOCKED** — a concrete dependency or failure prevents progress;
- **QUEUED** — ready to start;
- **NOT STARTED** — prerequisites are incomplete.

## 3. Implemented repository state

### Batch 01 — Repository toolchain

**State:** **IMPLEMENTED — OWNER VALIDATION PENDING**

Delivered Rust and Flutter workspace baselines, pinned toolchains, formatting/lint configuration, `scripts/validate.ps1`, CI and toolchain documentation.

### Batch 02 — Foundation contracts

**State:** **IMPLEMENTED — OWNER VALIDATION PENDING**

Delivered dependency-free identifiers, bounded timestamp, command/event envelopes, error classification, cooperative cancellation and unit tests in `torca-foundation`.

Documentation: [`docs/0.1/FOUNDATION_CONTRACTS.md`](docs/0.1/FOUNDATION_CONTRACTS.md).

### Batch 03 — Protocol base

**State:** **IMPLEMENTED — OWNER VALIDATION PENDING**

Delivered:

- new `crates/protocol/torca-wire` workspace crate;
- protocol family, protocol version, message kind and flags primitives;
- fixed 52-byte version-1 binary header;
- typed envelope and correlation identifiers;
- default 4 MiB payload limit and 256 MiB hard ceiling;
- deterministic frame encoding and exact/slice decoding;
- incremental decoder for partial and concatenated frames;
- explicit encode/decode error taxonomy;
- compatibility and malformed-input unit tests;
- [`docs/0.1/WIRE_PROTOCOL.md`](docs/0.1/WIRE_PROTOCOL.md).

Design limitations:

- no messaging, pairing, relay or peer payload schemas;
- no encryption, authentication or replay protection;
- no protocol negotiation state machine;
- no serialization dependency;
- no transport or storage behavior.

## 5. Current work package

### Batch 04 — Identity domain

**State:** **QUEUED — NEXT**

Goal: implement local installation identity, public identity, profile rules and narrow repository/key-provider ports against in-memory test doubles.

Required deliverables:

- create the `torca-identity` crate;
- define installation and public identity IDs as domain-specific newtypes;
- define local identity/profile aggregate and lifecycle invariants;
- define public identity projection without private material;
- define key-provider and identity-repository ports;
- define create/load/update profile operations without SQLite or platform code;
- add in-memory test doubles and domain tests;
- document identity ownership, secret boundaries and deferred rotation behavior;
- update this progress document.

### Next exact action

Create the `torca-identity` crate using `torca-foundation`. Keep persistence and cryptographic algorithms behind ports; do not begin the SQLite adapter or concrete key generation in Batch 04.
