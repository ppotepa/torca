## 2. One-client refactor implemented on `main`

### Shared Flutter application

`apps/client` now contains only the single `flutter/` application root. The previous sibling Windows and Android application roots were removed.

The same UI code is used on every device:

- compact widths use routed screens;
- wide widths use a split conversation list + pane;
- both paths render the same `ConversationPane`;
- identity and pairing errors are handled through the shared gateway;
- native startup failure is visible and never silently falls back to memory state.

### Shared native transport

Added `crates/platform/torca-native`:

- builds `torca_bridge.dll` / `libtorca_bridge.so` as a `cdylib`;
- owns one `ClientEngineActor` and `EngineBridge`;
- exposes a narrow C ABI for identity creation, pairing start, message queueing and snapshots;
- uses explicit pointer/length UTF-8 arguments;
- returns presentation-safe result/snapshot JSON buffers;
- includes a committed C header and a native snapshot/redaction test.

Flutter now uses `FfiEngineGateway` as the default production transport. The old Windows/Android engine MethodChannel implementations and their Flutter test were removed.

### ClientEngine composition seam

`ClientEngine` is now generic over its inward-facing ports with in-memory types only as defaults. Repositories and the identity key provider can be injected without changing workflow code.

`ClientEngineActor` accepts a small `EngineRuntime` interface, keeping `EngineHandle`, `EngineBridge` and Flutter free of generic type explosion.

This removes the architecture blocker for production SQLCipher/RustCrypto/protected-key composition while retaining simple memory defaults for tests.

### Developer workflow

The only public PowerShell entrypoints are now:

```powershell
./scripts/build.ps1
./scripts/run.ps1
./scripts/deploy.ps1
```

Legacy public scripts for format/validate/check/package/lock refresh were deleted. Their behavior moved to `tools/build/Torca.Build.psm1`.

The internal build module owns:

- release metadata and architecture checks;
- Flutter/Dart toolchain preflight;
- Cargo lock refresh when stale;
- Rust/Dart formatting;
- generated bridge contract;
- Cargo check, Clippy and tests;
- Flutter pub/analyze/tests;
- standard Flutter Windows/Android scaffold bootstrap;
- Windows native Rust DLL builds;
- Android `cargo-ndk` bootstrap and arm64-v8a/x86_64 builds;
- release packaging and SHA-256 checksums.

Generated `windows/`, `android/` and Flutter `.metadata` are ignored build scaffolds. Torca-specific Android manifest/activity/Keystore source is retained as an internal overlay under `tools/build/overlays/android`.

CI now calls the same canonical workflow:

```powershell
./scripts/build.ps1 -Target check -CI
```

## 5. Critical release gates

### GATE-001 — cryptography and protected keys

**OPEN.** Production algorithms and protected-store adapters exist, but the shared native constructor does not select them yet.

Remaining:

1. Windows native composition selects `RustCryptoProvider` + DPAPI-backed `ManagedIdentityKeys`.
2. Android Rust composition obtains a narrow JNI-backed Android Keystore `ProtectedSecretStore`; do not replace it with a memory/plain-file fallback.
3. SQLCipher database key provisioning uses protected platform storage.
4. Run target-device key lifecycle/negative tests.

### GATE-002 — SQLCipher persistence

**OPEN — adapter is validated, engine composition pending.**

Already owner-tested:

- bundled SQLCipher support;
- migrations;
- identity mapping;
- atomic message/outbox behavior;
- inbound dedup;
- file restart;
- wrong-key rejection;
- stale claimed-outbox recovery.

Remaining:

1. implement/select persistent contact/conversation/message/receipt repositories required by injected `ClientEngine`;
2. decide whether short-lived pairing sessions remain ephemeral or receive persistence;
3. provide the database path/key from platform composition;
4. commit the regenerated `Cargo.lock` used by the post-refactor build;
5. run process-kill tests against the composed client.

### GATE-003 — shared native Rust/Dart transport

**OPEN — shared ABI source is now implemented; target validation and production composition remain.**

Implemented:

- `torca-native` cdylib;
- stable C header;
- Dart `FfiEngineGateway` shared by Windows/Android;
- contract-version rejection;
- explicit no-memory-fallback startup behavior;
- engine lifetime owned in Rust;
- old duplicated engine MethodChannels removed.

Remaining:

3. replace `ClientEngine::default()` in native composition with production ports;
4. lifecycle/shutdown testing.
