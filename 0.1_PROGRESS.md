## 3. Implemented architecture

Committed source now includes:

- `torca-foundation` shared IDs, time, command/event, cancellation and errors;
- identity, contacts, pairing, conversations, messaging, receipts and attachments mini-domains;
- compile-time parameterized SQL, ordered migrations, outbox, claim recovery and dedup contracts;
- separate signing/sealing key semantics and crypto provider boundary;
- generic wire, relay and authenticated peer codecs;
- ephemeral in-memory rendezvous broker;
- single-writer ClientEngine and immutable snapshots;
- Tor process lifecycle, v3 onion configuration and SOCKS5 connector;
- generated bridge DTO source and Dart consistency checker;
- shared Flutter identity, pairing, contacts, conversation and diagnostics views;
- platform lifecycle policy and Windows/Android composition manifests;
- atomic encrypted blob storage, diagnostic ring buffer and fault injection;
- primary cross-crate journey test, threat model, test matrix, release metadata and packaging scripts.

## 6. Required owner validation

First format generated/source files:

```powershell
./scripts/format.ps1
```

Then run:

```powershell
./scripts/validate.ps1
```

The suite checks release metadata, architecture boundaries, generated contracts, Rust compilation/Clippy/tests and Flutter dependencies/analysis/tests.

Platform and integration work then follows [`docs/0.1/TEST_MATRIX.md`](docs/0.1/TEST_MATRIX.md) and [`docs/0.1/RELEASE_CHECKLIST.md`](docs/0.1/RELEASE_CHECKLIST.md).
