### Final source evidence

- one responsive Flutter client; no separate desktop/mobile business implementation;
- System/Light/Dark theme persistence and focused Settings;
- reusable status/connection primitives and runtime-owned PeerHealth;
- bridge v10 with nested `PeerHealthDto`; schema and generated Dart contract are byte-identical;
- connection details/header, message bubbles, shared actions, attachment UX, pairing UX and diagnostics dashboard;
- Windows tray/status and notification preference integration;
- Android foreground service reads a native persisted user-message notification preference independently from Flutter Activity lifetime;
- notification bodies remain content-free and Android service projection remains metadata-only;
- desktop shortcuts/focus traversal and standard padded Material targets are present;
- no stale Bridge v9 or superseded FFI gateway references found in the final repository audit.

## Tracked presentation-boundary debt

Bridge commands still accept some entity IDs/timestamps generated by Flutter. Revisit in 0.2 only with an intentionally versioned command-contract change.
