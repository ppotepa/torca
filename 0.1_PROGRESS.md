### Completed UI evidence

- UI-01: startup-loaded `themeMode`/`notificationsEnabled`; no preview preference; controlled temp export maintenance moved to Rust.
- UI-02: shared System/Light/Dark Material 3 themes and semantic colors.
- UI-03: focused Settings and shared application menu.
- UI-04: reusable canonical Tor/peer connection presentation.
- UI-05: runtime-owned PeerHealth probing over the authenticated peer link.
- UI-06: bridge v10 exposes nested `PeerHealthDto` through native JSON and the canonical FFI gateway.
- UI-07: conversation/contact surfaces expose live connection health without inventing presence.
- UI-08: reusable message bubbles, reply quote, timestamps and lifecycle icons.
- UI-09: shared touch/desktop action models for messages and conversation/contact rows.
- UI-10: reusable attachment tile with media icons, human sizes/progress and existing transfer actions.
- UI-11: pairing progress reflects existing runtime states without adding a Flutter workflow.
- UI-12: Diagnostics now leads with a human-readable dashboard derived only from supported bridge/diagnostic data; self-test/export remain available and raw redacted JSON is moved behind an expandable developer section. No unsupported health claims are fabricated.

Owner validation open: Rust build/tests, `flutter analyze`, `flutter test`, diagnostics export/self-test, pairing/attachment flows, desktop/touch checks, and real two-client runtime validation.
