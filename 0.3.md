# Torca 0.3 architecture-boundary plan

**Document type:** current engineering plan.  
**Detailed handoff:** [`docs/STATUS.md`](docs/STATUS.md).  
**Evergreen architecture:** [`ARCHITECTURE.md`](ARCHITECTURE.md).

The 0.3 work track closes remaining Dependency Inversion gaps between application, infrastructure and platform layers. It does not replace the valid domain graph or create crates solely to mirror an architecture diagram.

The `0.3` label is an engineering-track label, not a claim of a stable public release. Package/build versioning can move independently.

## Completed architecture stages

1. Enforce Cargo dependency/source guardrails without permanent architecture exceptions.
2. Keep typed peer/inbound vocabulary application-owned and keep the concrete Tor driver in infrastructure.
3. Keep read-state/receipt planning in application with one domain-owned deterministic receipt-ID rule.
4. Use `ClientApplicationRuntime` as the facade for commands, readiness, bootstrap and presentation projections.
5. Keep the generated contract as DTO/schema/serialization mapping rather than a second application runtime or security-policy owner.
6. Keep native code as process composition/ABI/JNI with one application runtime and platform services.
7. Compose presence and notification intent through domain/application ownership rather than platform-owned business logic.
8. Keep Flutter on generated typed states/resource IDs and protocol-owned invitation URIs instead of inferring workflow results from snapshot differences.
9. Validate the architecture through source policy, Rust/Flutter checks and supported-platform artifact builds when those gates are actually executed.

## 0.3 invariants

- Domain and protocol crates do not depend on application, infrastructure or platform implementations.
- Application crates do not depend on infrastructure or platform implementations.
- Versioned external representations belong to protocol/contract boundaries.
- Repositories own persistence and transactions, but not product policy.
- The presentation contract does not execute use cases, readiness logic or security algorithms.
- Native owns composition and process lifecycle, not application workflow.
- Flutter owns presentation and transient view state, not durable protocol/workflow state machines.
- Arti/Tor ownership remains isolated behind the Tor infrastructure boundary.
- Long-running network work must not block access to local encrypted state.
